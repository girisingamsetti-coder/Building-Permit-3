### 3. `src/components/officer/officer-review.tsx` — full rewrite of the action layer
- Removed imports of `WORKFLOW_STAGES` from `@/data/mock-data` and the obsolete `applicationsForRole` / `canUserActOnStage` helper.
- Imported `getStage` from `@/data/workflow-config` and `getAllowedActions` from `@/lib/permissions`.
- Action bar is now **driven entirely by `getAllowedActions(user, app)`** — the buttons rendered exactly match the workflow actions the user is permitted to perform at the current stage.
- Added `SUBMIT_TECHNICAL_SCRUTINY` and `REJECT` as distinct action buttons (previously missing). `FINAL_DECISION` is no longer a button — the Commissioner uses `APPROVE`/`REJECT` at `COMMISSIONER_REVIEW` and the store automatically promotes to `APPROVED` when applicable.
- Every action button opens a dialog and calls the corresponding store action:
  - `SUBMIT_TECHNICAL_SCRUTINY` → ActionDialog → `submitTechnicalScrutiny(appId, remarks)`
  - `FORWARD` → ActionDialog → `forwardApplication(appId, remarks)`
  - `APPROVE` → ActionDialog (with optional Conditions field) → `approveApplication(appId, remarks)`
  - `RETURN` → ActionDialog (reason required) → `returnApplication(appId, remarks)`
  - `REJECT` → ActionDialog (reason required) → `rejectApplication(appId, remarks)`
  - `RAISE_SHORTFALL` → ShortfallDialog → `raiseShortfall(appId, { type, title, description, dueDate })`
  - `ADD_REMARKS` → RemarksDialog → `addRemark(appId, text, type)`
- After each successful action, a descriptive success toast is shown and the user is navigated back to the assigned queue (so the updated state is visible).
- Added **Decision recorded banner** when `app.status === "APPROVED" || app.status === "REJECTED"` — hides the entire action bar.
- Added **Shortfall active banner** when `hasOpenShortfall(app)` is true — `getAllowedActions` automatically restricts the visible actions to `RAISE_SHORTFALL` + `ADD_REMARKS` in that case (handled in `permissions.ts`).
- Added **ShortfallResolutionSection** in the left pane: rendered when any shortfall has status `RESPONDED` or `UNDER_REVIEW`. Shows shortfall details, LTP response text + supporting document, and three buttons:
  - **Mark Under Review** (only when `RESPONDED`) → `reviewShortfallResponse(appId, shortfallId)`
  - **Resolve** → opens `SimpleShortfallDialog` (mode=resolve) → `resolveShortfall(appId, shortfallId, resolution)` — store auto-resumes workflow when all shortfalls resolved.
  - **Reopen** → opens `SimpleShortfallDialog` (mode=reopen) → `reopenShortfall(appId, shortfallId, reason)`
- Documents tab: **TPA-only verify/reject buttons**. When `user.role === "TPA"`, each uploaded document row shows a green "Verify" (`BadgeCheck`) icon button and a red "Reject" (`XCircle`) icon button. Verify calls `verifyDocument(appId, docId)` (which auto-generates fee when all required docs verified). Reject opens a dialog requiring a reason and calls `rejectDocument(appId, docId, reason)`.
- EmptyState fallback when `useSelectedApplication()` returns null or `user` is null — with a button to `navigate("officer-applications")`.
- Split-screen layout (`grid lg:grid-cols-[45%_55%]`), DrawingViewer, scrutiny report table with severity badges, mobile pane toggle — **all preserved unchanged**.
